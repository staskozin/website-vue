# План задач по устранению архитектурных проблем

Дата: 2026-04-04
Репозиторий: `website-vue`

## P1. Убрать хрупкий alias на внутренний путь `node_modules`

- Проблема:
  В `nuxt.config.ts` используется alias `pinia` на внутренний файл зависимости.
- Решение:
  1. Удалить alias `pinia` из `nuxt.config.ts`.
  2. Если Pinia нужна, подключить ее штатно через `@pinia/nuxt`.
  3. Если Pinia не используется, не добавлять лишних зависимостей.
- Критерии готовности:
  1. В конфиге нет alias на транзитивные пути.
  2. `npm run build` проходит без регрессий.

## P1. Развязать слой `components` от слоя `pages`

- Проблема:
  Компоненты импортируют типы из `pages/rice-calculator.vue`.
- Решение:
  1. Создать общий модуль типов, например `types/rice-calculator.ts`.
  2. Перенести туда `Purpose`, `RiceType`, `Pot`.
  3. Обновить импорты в странице и компонентах.
- Критерии готовности:
  1. В `components/*` нет импортов из `pages/*`.
  2. Проверка `rg -n "\.\./pages|pages/" components` не находит нарушений.

## P2. Вынести бизнес-логику калькулятора из страницы в composable

- Проблема:
  Логика состояния, правила доступности опций и вычисления смешаны с UI в `pages/rice-calculator.vue`.
- Решение:
  1. Создать `composables/useRiceCalculator.ts`.
  2. Перенести туда состояние, `watch`, `computed`, опции и формулы.
  3. В странице оставить сборку интерфейса и вызов composable.
- Критерии готовности:
  1. Страница содержит в основном шаблон и связывание с composable.
  2. Логику можно переиспользовать без копирования кода.

## P2. Отделить данные проектов от компонента отображения

- Проблема:
  Каталог проектов зашит в `components/ProjectList.vue`.
- Решение:
  1. Вынести данные в `content/projects.ts` (или `data/projects.ts`).
  2. Описать единый тип `ProjectItemModel`.
  3. В `ProjectList.vue` оставить только рендер списка.
- Критерии готовности:
  1. Компонент не содержит большой in-file массив с контентом.
  2. Добавление нового проекта не требует правок в шаблонной логике.

## P2. Разнести компоненты по доменным папкам

- Проблема:
  Плоская структура `components` усложняет навигацию и повышает связность при росте проекта.
- Решение:
  1. Разнести компоненты по зонам ответственности:
     - `components/features/projects/*`
     - `components/features/rice-calculator/*`
     - `components/shared/*`
  2. Сохранить совместимость использования компонентов (через настройки auto-import или явные импорты).
  3. Обновить все вхождения после переноса.
- Требования:
  1. Без изменения поведения интерфейса.
  2. Не ломать текущие шаблоны из-за смены имен auto-import.
  3. Для новых компонентов обязательно правило размещения: `shared` или конкретная `feature`.
  4. Добавить короткий гайд по структуре в `components/README.md`.
- Критерии готовности:
  1. `npm run build` проходит.
  2. Структура компонентов отражает домены, а не случайный рост файлов.
  3. Команда понимает правило размещения из документации.

## P3. Перенести конфигурацию аналитики в `runtimeConfig`/env

- Проблема:
  ID метрики захардкожен в `nuxt.config.ts`.
- Решение:
  1. Добавить `runtimeConfig.public.yandexMetrikaId`.
  2. Читать значение из переменной окружения (например, `NUXT_PUBLIC_YANDEX_METRIKA_ID`).
  3. Подставлять значение в модуль метрики из конфига.
- Критерии готовности:
  1. В репозитории нет хардкода production ID.
  2. Для локального и production окружений можно задать разные значения.

## P3. Добавить архитектурные проверки в CI

- Проблема:
  Нет автоматических guardrail-проверок на нарушения границ слоев.
- Решение:
  1. Добавить скрипт архитектурной проверки (например, на базе `rg` или ESLint import rules).
  2. Проверять минимум два правила:
     - `components` не импортируют `pages`;
     - запрет alias на внутренние файлы зависимостей.
  3. Запускать проверку в CI перед сборкой.
- Критерии готовности:
  1. Нарушения ловятся автоматически до merge.
  2. Документация по правилам добавлена в `README.md`.

## Рекомендуемый порядок внедрения

1. Убрать alias `pinia`.
2. Вынести общие типы и разорвать импорт `components -> pages`.
3. Вынести логику рис-калькулятора в composable.
4. Вынести каталог проектов в data/content слой.
5. Разнести компоненты по доменным папкам.
6. Перенести метрику в env/runtimeConfig.
7. Добавить CI-guardrails.
